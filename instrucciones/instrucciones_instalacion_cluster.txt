---------------------------------------------------------------------------
INSTRUCCIONES ARRANQUE Y REPRODUCCIÓN
---------------------------------------------------------------------------

1.) Instalamos WSLv2 en nuestra máquina Windows y lo activamos

2.) Instalamos Podman Desktop en windows. Para crear la máquina inicial, es necesario que esta
cuente con permisos de root, por lo que debemos hacer este ajuste cuando arranquemos la máquina
por primera vez.

El nombre de la máquina debe ser podman-machine-teleupm

Debemos también marcar las extensiones de Compose y Kubectl para configurarlas y usarlas en
los siguientes pasos

Debemos marcar la opción de "Machine with root privileges" y la de "User mode networking (traffic relayed by a user process)"

3.) Importante instalar sobre podman el proveedor de podman-compose para que funcione la
instalacion, así como kubectl.

Esto lo podemos hacer desde Podman Desktop yendo a Settings (engranaje abajo a la izquierda) > Resources.
De ahí, le damos a "Set up" en las extensiones configuradas de Kubectl y Compose de antes

4.) Para poder subir imágenes a la cuenta, debemos configurar Docker Hub como registro principal. Para ello,
ejecutaremos en orden...

[ podman machine ssh podman-machine-teleupm  ]
[ sudo vi /etc/containers/registries.conf ]

Aquí, ponemos solo una línea así (Definición v2 del registro docker
por defecto)...

unqualified-search-registries = ["docker.io"]

[ exit ]

La configuración debe quedar sobre la parte de Resources tal cual se puede ver en la captura de pantalla
"configuracion_podman.png" de esta carpeta.
Ajustaremos la RAM y CPU en función de nuestra máquina

5.) Ajustamos la CPU y RAM de la máquina virtual de podman. Para ello, ejecutamos el fichero "ajuste_CPU_RAM.ps1"
de esta misma carpeta ajustando los parámetros a nuestro gusto. Es posible que necesitemos cambiar la
política de ejecución de scripts de Powershell para poder ejecutarlo.

6.) Modificamos el fichero hosts (C:\Windows\System32\drivers\etc\hosts)
como administrador para añadirle las siguientes rutas...

127.0.0.1  teleupm.com
127.0.0.1  argocd.teleupm.com
127.0.0.1  jenkins.teleupm.com

7.) Tenemos que decirle a fireabase que "teleupm.com" es seguro para hacer login desde esa
página. De lo contrario, el login con Google fallará en la app de gestión web.

Para ello, debes registrarlo en dos plataformas:

- Consola de Firebase (Dominios Autorizados):

Entra a tu proyecto en la consola de Firebase.

Ve a Authentication > Settings (Configuración) > Authorized domains.

Añade teleupm.com a la lista.

- Google Cloud Console (Credenciales OAuth - El paso crítico):
Firebase crea por debajo un cliente OAuth en Google Cloud para gestionar el botón de login, y este tiene sus propias reglas estrictas.

Entra en console.cloud.google.com y selecciona el proyecto de Google Cloud que corresponde a tu Firebase.

En el menú lateral, ve a API y Servicios > Credenciales.

En la sección "ID de cliente de OAuth 2.0", haz clic en el cliente web de tu proyecto (suele llamarse "Web client (auto created by Google Service)").

En el apartado Orígenes autorizados de JavaScript, añade exactamente tu URL con HTTPS: [https://teleupm.com](https://teleupm.com)

En el apartado URI de redireccionamiento autorizados, añade la ruta estándar que usa Firebase: [https://teleupm.com/__/auth/handler](https://teleupm.com/__/auth/handler)

Guarda los cambios (Tarda de 5 a 10 minutos en aplicarse).

7.) Para importar el certificado, en esta demostración se usó chrome.

Importamos el certificado "certs/cert_CA_tfg_tsi.cer" Menú lateral > Configuración > Privacidad
y seguridad > Seguridad > Gestionar certificados > Instalados por ti", y hacemos click en el 
botón de "Importar".

De ahí, seleccionamos el certificado mencionado para instalarlo. Cerramos y abrimos chrome
para que se apliquen los cambios

8.) Ejecutamos el fichero "crear_cluster.bat" en una terminal de Windows

---------------------------------------------------------------------------
TROUBLESHOOTING
---------------------------------------------------------------------------

Si al utilizar el script "reanudar_cluster.bat" ocurre una de las
siguientes cosas...

- No funciona la conexión al npipe de Podman
- K0s pierde el acceso al nodo (NodeNotReady como estado
de algún Deployment por pérdida de acceso a kubelet),
o no llegas a las IP de los ingress

Ejecutar el fichero "parar_cluster.bat" y acto seguido, "reestablecer_red_podman.ps1".

Este comportamiento se debe al inicio rápido de Windows, que deja las conexiones
de Podman colgadas en segundo plano y los procesos de red de Windows pillados (hang up)
